SCOPE — WHAT GOES IN PR #7
────────────────────────────────────────

The actual Firebase Phone Auth integration. Specifically:

  - An auth repository (`lib/features/auth/data/phone_auth_repository.dart`) with methods:
      * `requestOtp(phoneNumber: String) → Future<VerificationSession>`
      * `verifyOtp(session: VerificationSession, code: String) → Future<AuthUser>`
      * `resendOtp(session: VerificationSession) → Future<VerificationSession>`
      * `signOut() → Future<void>`  (placeholder for FR-AU-08, used internally for cleanup)
   - These wrap `firebase_auth.signInWithPhoneNumber` and the verifyId/code flow correctly. Use `verifyPhoneNumber` on Android (to support SMS Retriever auto-read per FR-AU-04) and `signInWithPhoneNumber` on iOS.
   - The phone-entry controller's submit (currently a stub from PR #4) now calls `requestOtp` and navigates to OTP screen on success. On failure, shows the inline error from the screen spec.
   - The OTP controller's submit (stub from PR #6) now calls `verifyOtp`. On success, navigates to a placeholder "Authenticated" home screen (the real home dashboard is later). On failure, shows the inline error from the OTP screen spec.
   - The OTP controller's resend (stub from PR #6) now calls `resendOtp` and resets the 30-second countdown.
   - The 3-retry-per-10-minute cooldown rule (FR-AU-05) is enforced client-side. After 3 resends in a 10-minute window, the resend button stays disabled and shows the spec-specified error.
   - SMS Retriever integration on Android: when an inbound OTP SMS matching the app's hash is received, the OTP fields auto-fill. iOS retains manual entry only (FR-AU-04).
   - Telemetry events added in this PR:
      * `signup_otp_sent` (on successful `requestOtp`).
      * `signup_otp_send_failed` (with error code, no PII).
      * `signup_otp_verified` (on successful `verifyOtp`).
      * `signup_otp_verify_failed` (with error code).
      * `signup_otp_autofilled` (Android only, when SMS Retriever populates).
      * `signup_otp_resend_blocked` (when 3-per-10-min cap hit).

DO NOT include in PR #7:
  - Profile setup screen (FR-AU-06) — PR #8.
  - Session persistence beyond what `firebase_auth` provides natively (FR-AU-07 verification is later).
  - Sign-out UI (FR-AU-08) — later PR.
  - User document creation in Firestore. The first time a user signs in, a Cloud Function will create the user doc. That Cloud Function is part of PR #8; for PR #7, post-auth navigation is a placeholder screen that just says "Authenticated — user record creation comes next PR".
  - reCAPTCHA Enterprise wiring (handled by firebase_auth automatically; document in the PR body, do not add custom integration).
