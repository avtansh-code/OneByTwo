SCOPE — WHAT GOES IN PR #6
────────────────────────────────────────

The OTP entry SCREEN only. No Firebase Auth call. Specifically:

  - The screen widget (`lib/features/auth/presentation/otp_entry_screen.dart`).
  - A six-digit OTP input widget that:
      * Renders six individual character cells per the mockup.
      * Auto-advances focus on each digit entered.
      * Auto-collapses focus on backspace.
      * Accepts paste of a six-digit string.
      * Exposes the assembled OTP value via the controller.
  - A Riverpod controller for OTP entry state (`lib/features/auth/application/otp_entry_controller.dart`):
      * Holds the current OTP digits.
      * Exposes `isComplete`, `canSubmit`, and `validationError`.
      * Provides a `submit()` callback that takes a function injected by the screen — for THIS PR, that injected function is a stub that just logs `signup_otp_submitted` to telemetry and pops the route.
  - Resend timer UI:
      * 30-second countdown (per FR-AU-05).
      * "Resend OTP" link disabled while counting; enabled at zero.
      * Counter resets on resend.
      * Resend button currently calls a stub callback that logs `signup_otp_resend_requested`. Real wiring is PR #7.
  - "Edit phone number" affordance that pops back to the phone-entry screen.
  - All states from the screen spec: default, partial entry, full entry validating, full entry valid, paste-from-SMS, error state with copy from the spec, dark mode, dynamic-type extra-large, TalkBack/VoiceOver labelled.
  - Telemetry events fired in this PR:
      * `signup_otp_screen_viewed` on screen mount (with phone number HASHED, not raw — PII rule from SRS §5.4).
      * `signup_otp_submitted` on stub submit.
      * `signup_otp_resend_requested` on stub resend.

DO NOT include in PR #6:
  - `firebase_auth.signInWithPhoneNumber()` or any actual Auth call.
  - SMS Retriever auto-read on Android (that comes in PR #7).
  - Any verification logic — submission is a stub.
  - Profile setup screen (PR #8).
  - Session persistence (later PR).
