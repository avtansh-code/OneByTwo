20. 2. **Golden bytes are host-sensitive — author baselines on `ubuntu-latest`, NEVER on this macOS machine (Darwin).** This is the load-bearing logistical constraint and the single most common DC-13 failure. Flutter's rasteriser produces different bytes on macOS vs Linux, so a `flutter test --update-goldens` run on this session's host would commit baselines that the `ubuntu-latest` compare job then **rejects**. The canonical flow (already specified in `04-qa-test-strategy.md` §E.2 / §A.2.2 / §A.3) is: add a **`golden-refresh` `workflow_dispatch`-only** job (or step) that runs `flutter test --update-goldens` on `ubuntu-latest` and uploads the regenerated PNGs as an artifact; the developer downloads that artifact and **commits the baselines**; the comparison job then passes against them. **Do not author or commit golden PNGs produced locally on macOS.** If you cannot reach the ubuntu refresh path, stop and surface it — do not paper over it with macOS bytes.
21.
22. 3. **Bundle the type families for determinism — `google_fonts` runtime fetch is non-deterministic and offline-fails in CI.** `lib/app/theme.dart` builds the `TextTheme` via `GoogleFonts.bricolageGrotesque()` / `GoogleFonts.hankenGrotesk()` (`google_fonts: ^6.2.1`); there are **no `.ttf` files in the repo today** and `loadHaldiFonts()` only disables runtime fetching. DC-13 must obtain the **Bricolage Grotesque** and **Hanken Grotesk** `.ttf` (both **SIL OFL 1.1**, which permits bundling — keep the licence text), add them as **test assets** (e.g. under `test/golden/fonts/`), and load them through a `FontLoader` inside `loadHaldiFonts()` so the golden text rasterises identically on every host. Confirm the loaded family names match what the theme resolves so the goldens render the real type ramp, not a fallback.
23.
24. 4. **The golden job is SEPARATE from DC-12's `a11y-checks` gate, and multi-tag selection MUST use the boolean-OR selector.** DC-12 already wired the named **"Accessibility Gate (WCAG AA)"** job (`a11y-checks`) running `flutter test --tags "a11y-contrast || a11y-dynamic-type"`. DC-13 adds the **`golden-a11y-checks`** ubuntu job per `04-qa-test-strategy.md` §E.2 (the draft block is illustrative). **Critical:** `flutter test --tags a --tags b` is **last-wins** and silently runs only the last family (verified in DC-12: the repeated form ran 6 of 26 tests). Use the boolean-OR selector — `flutter test --tags "golden || a11y-contrast || a11y-dynamic-type"` (the §E.2 draft was corrected to this in DC-12). Keep `flutter test --exclude-tags golden` fast for developers (Appendix 2 intent). On a golden failure, upload Flutter's `failures/*_testImage.png` / `*_masterImage.png` / `*_isolatedDiff.png` / `*_maskedDiff.png` so reviewers see the pixel diff without re-running.
