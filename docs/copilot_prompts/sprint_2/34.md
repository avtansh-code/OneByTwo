## 2. Numbering / CI title-lint gotcha

The PR title lint (`.github/workflows/pr.yml`) enforces `^(feat|fix|chore|docs|test|refactor|ci|build)(\([a-z0-9_-]+\))?!?: .{1,72}$` — a single-token scope (no commas) and subject <= 72 chars. Keep the title ASCII (avoid the em-dash; the byte-count can surprise the `.{1,72}` check). Suggested title (<= 72 chars): `docs(conventions): PR coverage fields, CF checklist, friends mockup`. Branch: `docs/sprint-2-docs-closeout` (repo convention: type-prefixed kebab). This PR touches `docs/**` + `.github/PULL_REQUEST_TEMPLATE.md` only — NO `lib/**` or `functions/**`, so the lefthook pre-commit `dart format` / `flutter analyze` / `eslint` globs do not match and the pre-push coverage gate is a no-op (no `lib/features/**` or `functions/src/**` touched). Commit with **`fvm exec git commit`** anyway for consistency; push with **`fvm exec git push`**. CI's Flutter / Functions jobs have nothing to compile, so a clean docs PR passes them trivially; the live gate is the Title Lint.
