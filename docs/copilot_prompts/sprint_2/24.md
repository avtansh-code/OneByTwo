## 1. Scope — what we build

FR-PR-04 (SRS section 4.7, line 177, **P0**) on **SCR-26 Profile** (`docs/design/06-screen-specs/23-28-settle-activity-profile.md` §SCR-26, lines 391+): the Profile screen's Stats section shall show a live **"My Friends" count** with a row that **navigates to the Friends tab** (tab index 1), and a **"My Groups" count** with a row that navigates to the Groups tab (tab index 2). Today both rows hardcode `0` and snackbar "Coming soon".

RECOMMENDED scope (ship this):

- **Live friend count — compose the existing provider, no new data layer.** The friendship axis already exists: `friendsListProvider` (`lib/features/friends/application/friends_list_provider.dart`, `StreamProvider<List<FriendListItem>>`). The "My Friends" count is `items.length`. Add a small derived provider (e.g. `friendCountProvider` in `lib/features/profile/application/`) that projects `friendsListProvider.whenData((items) => items.length)`. It MUST declare `dependencies: [friendsListProvider]` because `friendsListProvider` is itself scoped on the per-arm `currentUserIdProvider` override — this is the exact Riverpod-scoping rule PR #62 established: a provider that watches a scoped provider lists THAT provider, not the transitive root, or Riverpod throws "specified a 'dependencies' list" at first read. Render the async sub-states on the row: loading (em dash / skeleton), data (the integer), error (em dash — never a crash), empty (`0`).

- **Programmatic tab navigation — introduce `shellNavigationControllerProvider` (the architectural first).** Today `AuthenticatedShell` owns the active tab as a plain in-shell `int _currentIndex` mutated by `setState` (`lib/features/shell/presentation/authenticated_shell.dart`); architect note §2.2 deferred a Riverpod `Notifier<int>` "until a second consumer needs it". **FR-PR-04 IS that second consumer.** Introduce a `shellNavigationControllerProvider` (a Riverpod `Notifier<int>` exposing `selectTab(int)`), have the shell READ it for `IndexedStack.index` and WRITE it from `_onTabSelected` (preserving the `bottom_nav_tab_selected` telemetry and the PopScope snap-to-tab-0), and have the Profile "My Friends" row call `selectTab(1)`. This is a contained refactor that closes the §2.2 deferral and the `next-three-prs.md` "shellNavigationControllerProvider + FR-AC-05 deep-link tab-switching" candidate. Do NOT push a duplicate `FriendsListScreen` via `MaterialPageRoute` — that would defeat the IndexedStack tab-state preservation and contradict the SCR-26 "tab index 1" contract.

- **Group axis stub.** Groups are not implemented (`lib/features/groups/` is README-only; Sprint 3 epic). The "My Groups" count is `0`; STUB it exactly as FR-HD-02 (PR #62), FR-SE-08 (PR #58), and FR-HD-04 (PR #57) did. Architect's call at kickoff: either (a) the "My Groups" row navigates to tab 2 (the existing `GroupsListPlaceholder`) showing `0`, matching the SCR-26 "tab index 2" contract, or (b) it stays a disabled / "Coming soon" row until the Sprint 3 Groups epic. Prefer (a) for spec fidelity since the Groups tab already exists as a placeholder; no real group data renders either way.

- **Remove the stub.** Replace the hardcoded `'0'` + "Coming soon" snackbar `onTap` on both rows. Keep the `_ProfileRow` layout (leading icon, label, trailing count + chevron, 56 dp height) and the `'My Friends, [count], button'` / `'My Groups, [count], button'` accessibility labels (SCR-26 a11y table) — now with the live count.

- **Telemetry.** Emit row-tap events — e.g. `profile_friends_tapped` and `profile_groups_tapped` — following the existing profile telemetry pattern (`profile_viewed`, `sign_out_completed` are fired inline in `profile_screen.dart`). A friend count is a non-identifying integer, so per ADR-0013 these payloads carry **no PII** and need no hashing. These two events are NOT yet in the SCR-26 telemetry table — pre-declare them in `docs/design/07-technical/telemetry-plan.md` (or a per-feature constants file) as part of this PR.

- **No money rendering.** FR-PR-04 shows counts and navigation only — there is no balance on these rows, so Invariant 1 has no monetary surface here. Do NOT add balances to the Profile rows; that is out of scope.

## 5. Cross-cutting dependencies and risks

- **Shell-state refactor blast radius.** Moving `_currentIndex` out of `AuthenticatedShell` into `shellNavigationControllerProvider` touches the most-trafficked widget in the app. Preserve every existing behaviour: the `bottom_nav_tab_selected` telemetry on user taps (NOT on programmatic or back-driven switches), the PopScope snap-to-tab-0 on Android back, the FAB-hidden-on-Activity-tab rule, and the `@visibleForTesting tabContentOverride`. The existing `test/features/shell/**` suite (incl. `shell_boundary_contract_test.dart`) and `test/features/auth/auth_gate_test.dart` MUST stay green — update them only where the state ownership genuinely moved.
- **Riverpod scoping.** `friendCountProvider` must declare `dependencies: [friendsListProvider]` (PR #62 lesson). `shellNavigationControllerProvider` is root-scoped (no per-arm override) so it needs no `dependencies` list — but verify it is created ONCE at a scope visible to BOTH the shell and Profile, so they read the same instance (do not create it inside a per-arm `ProviderScope` that Profile cannot see).
- **No new Cloud Function, Firestore collection, security rule, index, or Flutter plugin.** This is a 100% client-side, read-only PR composing existing providers. **No `ios/Podfile.lock` change is expected.** If the architect nonetheless adds any plugin, run `cd ios && pod install --repo-update` and commit `ios/Podfile.lock` in the same PR (the Build iOS CI job runs a vanilla `pod install` and fails on a stale lock — verified PR #55 lineage).
