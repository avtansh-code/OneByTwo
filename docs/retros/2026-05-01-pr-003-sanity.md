## Skeleton choices that held up

- **Feature-first folder structure** (`lib/features/auth/`, `lib/core/`). PR #4 slotted
  implementation files and tests into the scaffolded directories without any restructuring.
- **Theme system** (`lib/app/theme.dart`). PR #4 consumed `AppTheme.light` and
  `AppTheme.dark` via `Theme.of(context)` and `colorScheme` throughout — no workarounds,
  no extensions needed.
- **Dependency pinning** (`pubspec.yaml`). PR #4 added zero new dependencies. Every
  package needed (Riverpod, Firebase Analytics, etc.) was already pinned in the skeleton.
- **Lint ruleset** (`analysis_options.yaml` with `very_good_analysis ^6.0.0`). PR #4
  passed `flutter analyze --fatal-infos` without any rule suppressions or overrides.
- **Riverpod ProviderScope** in `main.dart`. PR #4 wired providers directly — no
  initialisation conflicts.
- **Test mirror structure** (`test/features/auth/`). Tests landed in the expected
  location and the existing `widget_test.dart` was updated, not orphaned.

## Skeleton choices that need adjustment

1. **Firebase initialisation is absent from `main.dart`.** PR #3 deliberately deferred
   `Firebase.initializeApp()` because `firebase_options.dart` is gitignored and
   unavailable in CI. PR #4 attempted to add it (commit 9), then reverted it (commit
   10). The app currently does not initialise Firebase at startup, so any Firebase
   service call (`FirebaseAnalytics.instance`, `FirebaseAuth.instance`) would crash at
   runtime. **Action:** Create a dedicated bootstrap module (`lib/app/bootstrap.dart`)
   that conditionally initialises Firebase, with a test-mode bypass for CI. Owner:
   flutter-dev.

2. **CI pipeline was not prepared for Firebase-dependent builds.** PR #4 had to patch
   both `pr.yml` and `release.yml` to restore `google-services.json` and
   `GoogleService-Info.plist` from base64-encoded GitHub secrets. This caused three
   CI-fix commits (out of twelve total). **Action:** Document the secret-restoration
   pattern in the workflow files so future Firebase service integrations do not require
   CI patches. Owner: devops.

## Items deferred

- **`Podfile.lock` committed (1,660 lines).** Standard practice for Flutter iOS projects
  to ensure reproducible builds. Adds diff noise but the cost of gitignoring it (CI
  build non-determinism) outweighs the cost of noisy diffs. Leave as-is.
